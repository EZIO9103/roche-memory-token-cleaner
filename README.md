# 记忆低Token清理器

> Roche 事实记忆整理插件。  
> 用来整理过长、重复、流水账式的事实记忆，减少长期记忆占用，并让后续召回更稳定。  
> 当前说明按 **v3.5.5** 编写。

> **使用前请先备份聊天记录。**  
> 这个插件会整理、压缩、合并或删除 Roche 的事实记忆。虽然结果区会先给你确认，但 AI 仍然可能误判。进行大清洗、旧记忆归档、合并或删除操作前，请先备份当前聊天记录。

---

## 安装方式

在 Roche 插件安装处填写：

```text
https://ezio9103.github.io/roche-memory-token-cleaner/manifest.json
```

## 这个插件是做什么的

Roche 的事实记忆用久以后，可能会出现这些问题：

- 单条记忆太长，占用上下文。
- 多条记忆重复记录同一件事。
- 一条记忆里塞了很多天的流水账。
- 旧剧情已经结束，但仍然保留过多细节。
- 同一个完整事件被拆成很多碎片。
- 记忆顺序乱了，导致后续召回不稳定。

这个插件用于整理 **Fact Memory / 事实记忆**。  
它不会主动修改 **Core Memory**。

---

## 新手推荐用法

第一次使用，建议从低风险功能开始。

```text
重新读取记忆
→ 压缩过长/流水账
→ 查看/编辑结果
→ 应用全部结果
→ 修复记忆顺序
```

日常维护可以这样用：

```text
重新读取记忆
→ 清理新增
→ 查看/编辑结果
→ 应用全部结果
```

记忆很多、已经明显混乱时，再使用：

```text
大清洗
旧记忆归档
修复记忆顺序
```

> **顺序提醒：**  
> 除了「清理新增」以外，执行大清洗、压缩候选、旧记忆归档或合并已选后，建议再点一次「修复记忆顺序」。  
> 这样可以降低事实卡片顺序错乱导致 Roche 读取上下文出错的概率。

## 功能按钮说明

| 按钮 | 作用 | 适合什么时候用 |
|---|---|---|
| 重新读取记忆 | 重新读取当前会话的事实记忆 | 换会话、刚导入插件、记忆刚变化后 |
| 清理新增 | 只处理新增或变动过的事实记忆 | 日常维护 |
| 大清洗 | 审查全部事实记忆，可能压缩、拆分、合并或删除 | 记忆已经明显冗长、重复、混乱时 |
| 压缩过长/流水账 | 只处理“压缩候选” | 想保守处理，不想动全库时 |
| 旧记忆归档 | 把较早的细碎事实压缩成阶段性记忆 | 旧剧情已经结束，只想保留大概脉络时 |
| 修复记忆顺序 | 按时间字段整理事实记忆顺序 | 大清洗、归档、合并后建议使用 |
| 应用全部结果 | 把当前结果区的修改真正写回 Roche | 检查结果后最后点击 |

## 状态栏说明

| 状态 | 含义 |
|---|---|
| 事实记忆 | 当前读取到的 Fact Memory 数量 |
| 新增/变动 | 插件判断自上次记录后新增或变化的记忆 |
| 压缩候选 | 本地规则判断“可能值得压短”的记忆 |
| 估算 token | 当前事实记忆的大致 token 占用 |
| AI 结果 | 当前结果区里 AI 生成的处理结果数量 |
| 需处理 | 需要人工确认或检查的结果数量 |

### 什么是“压缩候选”

“压缩候选”不是必须删除，也不是一定有问题。  
它只是表示：这条记忆可能比较长、比较像流水账，或包含多个事件，值得让 AI 看一眼。

---

## 结果区怎么用

插件生成结果后，不会立刻写回 Roche。  
你看到的是一组可以继续编辑的草稿。

| 操作 | 含义 |
|---|---|
| AI重改 | 让 AI 重新处理当前这张结果卡 |
| AI压短 | 在当前结果基础上继续压缩 |
| 改为单条压缩 | 把拆分或删除建议改成单条压缩 |
| 保留原文 | 不使用 AI 修改，保留原始记忆 |
| 删除这条 | 标记这条事实记忆为删除 |
| 撤销 | 撤销当前手动标记 |
| 合并选择 | 勾选这张结果卡，准备和其他卡合并 |
| 合并已选 | 把已勾选的多张结果卡合成一张合并草稿 |
| 应用全部结果 | 真正写回 Roche 事实记忆 |

---

## 合并已选

当几张结果卡其实属于同一个已经结束的事件，可以用“合并已选”。

它适合处理这种情况：

```text
同一个事件被拆成好几条事实记忆。
前因、过程、结果分别存在不同卡片里。
这段事件已经结束，可以压成一条完整记忆。
```

使用方式：

```text
勾选要合并的结果卡
→ 点击合并已选
→ 检查新生成的合并草稿
→ 需要的话继续手动编辑或 AI压短
→ 最后点击应用全部结果
```

注意：

- 合并已选不会立刻写回 Roche。
- 它只会修改当前结果区。
- 被合并的旧草稿卡会从结果区移除。
- 新生成的合并卡仍然可以继续编辑。
- 最后只有点击“应用全部结果”才会真正写回事实记忆。

## 推荐使用场景

### 日常维护

适合经常游玩、记忆持续增长的情况。

```text
清理新增
```

特点：

- 处理范围小。
- 风险低。
- 适合频繁使用。

---

### 保守压缩

适合只想处理明显过长的记忆。

```text
压缩过长/流水账
```

特点：

- 不会主动审查全库。
- 主要处理压缩候选。
- 比大清洗更稳。
- 应用后建议再使用「修复记忆顺序」。

---

### 全库整理

适合记忆已经变多、变乱、重复明显时。

```text
大清洗
```

特点：

- 处理范围大。
- 会给出压缩、拆分、合并、删除等建议。
- 建议认真看结果区，不要盲点应用。
- 应用后建议再使用「修复记忆顺序」。

---

### 旧剧情退场

适合早期剧情已经不需要保留大量细节时。

```text
旧记忆归档
```

特点：

- 会把旧事实压成更概括的阶段记忆。
- 更像“人脑记得大概发生过什么”。
- 不适合处理刚发生的重要事件。
- 应用后建议再使用「修复记忆顺序」。

## 设置说明

### 数字设置

| 设置 | 默认值 | 作用 | 建议 |
|---|---:|---|---|
| 单条最大中文字数 | 180 | 超过这个长度的记忆更容易被列为压缩候选 | 默认即可；想保留更多细节可调高 |
| 偏好最短字数 | 80 | 控制 AI 压缩时不要压得太短 | 不建议太低 |
| 偏好最长字数 | 140 | 普通事实记忆压缩后的目标长度 | 默认即可 |
| 重大节点最长字数 | 220 | 重要事件允许保留更多细节 | 关系复杂时可适当调高 |
| 关键词数量上限 | 4 | 每条记忆最多附带几个关键词 | 3-4 通常够用 |
| AI批量审查条数 | 1 | 一次交给 AI 审查几条记忆 | 建议保持 1，最稳 |
| 读取长期记忆上限 | 300 | 插件最多读取多少条事实记忆 | 记忆很多时再调高 |
| 旧记忆归档条数 | 10 | 一次归档多少条旧记忆 | 新手建议 5-10 |

---

### 单条最大中文字数

用于判断哪些记忆可能太长。  
超过这个数的记忆更容易进入“压缩候选”。

建议：

```text
普通使用：180
想保留更多细节：220
想更强力压缩：140-160
```

---

### 偏好最短字数

告诉 AI：压缩时不要压得太短。  
如果设得过低，AI 可能只留下很薄的摘要，丢掉事件后果。

建议保持默认。

---

### 偏好最长字数

告诉 AI：普通事实记忆压缩后大概控制在多长。  
这不是硬性截断，而是压缩目标。

建议保持默认。

---

### 重大节点最长字数

有些记忆比普通日常更重要，例如：

- 关系转折
- 边界确认
- 冲突与和解
- 承诺
- 离别
- 长期状态变化

这些记忆可以比普通事实更长。  
如果你的角色关系线较复杂，可以适当调高。

---

### 关键词数量上限

控制每条事实记忆最多附带几个关键词。  
关键词越多，召回线索越多，但记忆正文也会更杂。

建议保持默认值 `4`。  
如果你不想让记忆末尾出现关键词，可以关闭“关键词写回主记忆”。

---

### AI批量审查条数

控制一次交给 AI 处理几条记忆。

建议保持 `1`。  
批量越大，AI 越容易混淆不同记忆，也更容易出现格式问题。

---

### 读取长期记忆上限

控制插件最多读取多少条事实记忆。

如果你的事实记忆很多，默认值可能只读到一部分。  
可以适当调高，但读取和处理都会更慢。

---

### 旧记忆归档条数

控制一次归档多少条旧记忆。

建议新手先用 `5-10`。  
一次归档太多，结果会更难检查，也更容易误伤重要旧事。

---

## 高级开关说明

| 开关 | 默认 | 作用 | 建议 |
|---|---|---|---|
| 全部执行AI建议 | 关 | 降低人工确认门槛，更倾向直接执行 AI 结果 | 新手关闭 |
| 关键词写回主记忆 | 开 | 在事实正文末尾写入关键词 | 一般开启 |
| UTC时间模式 | 关 | 更保守地处理带 UTC 的时间 | 不懂就默认 |
| Tag英文优先 | 关 | 英文内容较多时，让关键词优先用英文 | 英文内容多时开启 |
| 显示Core Memory | 关 | 显示 Core Memory 供查看 | 需要查看时开启 |

---

### 全部执行AI建议

开启后，插件会更少要求你逐条确认。  
适合已经熟悉插件、且当前记忆风险较低的情况。

新手不建议开启。  
第一次清洗某个会话时，也不建议开启。

---

### 关键词写回主记忆

开启后，插件会把关键词写到事实记忆正文末尾。  
这样可以增加后续召回线索。

如果你不喜欢记忆正文末尾出现关键词，可以关闭。

---

### UTC时间模式

用于更保守地处理带 UTC 标记的时间。

它不会把所有时间强行转换成 UTC。  
它主要用于避免旧记忆里没有标注时区的时间被错误精算。

如果你不确定，一般保持默认即可。

---

### Tag英文优先

开启后，关键词会更倾向使用英文自然短语。  
适合英文内容较多的会话。

关闭时，中文、英文、中英混合都允许。  
如果你的会话本身中英混合，保持关闭也可以。

---

### 显示Core Memory

开启后可以查看 Core Memory。  
插件不会修改 Core Memory。

## 常见问题

### Q：清理新增显示 0，是不是插件坏了？

不是。  
这表示插件没有发现新增或变动的事实记忆。

这时可以改用：

```text
压缩过长/流水账
```

或：

```text
大清洗
```

---

### Q：压缩候选还有很多，是不是没清干净？

不一定。  
压缩候选只是本地粗筛，不代表一定有问题。

有些记忆即使已经整理过，只要仍然比较长，仍然可能被标记为压缩候选。

---

### Q：合并已选会不会立刻改我的记忆？

不会。  
合并已选只会修改当前结果区草稿。  
真正写回要等你点击“应用全部结果”。

---

### Q：为什么合并后旧卡片消失了？

这是正常行为。  
被合并的草稿卡会从结果区移除，换成一张新的合并草稿。

这样可以避免最后应用时重复写回。

---

### Q：什么时候用大清洗，什么时候用压缩过长/流水账？

如果你只是想保守处理明显过长的记忆，用：

```text
压缩过长/流水账
```

如果你想重新审查全部事实记忆，用：

```text
大清洗
```

---

### Q：旧记忆归档会不会删除重要记忆？

它可能会把旧记忆合并、压缩或建议删除。  
所以建议先少量归档，并检查结果区。

不确定时，不要一次归档太多。

---

### Q：重装后索引丢了，不想重新清洗怎么办？

点「修复记忆顺序」。

这是最省 token、也最省事的恢复方式。它不会重新大清洗，只会根据现有记忆的时间字段整理顺序，适合重装、清缓存或换设备后恢复基础状态。

---

### Q：插件会修改 Core Memory 吗？

不会。  
插件主要处理 Fact Memory。  
“显示Core Memory”只是查看用。

---

## 使用提醒

- 第一次使用前，建议先备份当前角色或会话。
- 不确定的 AI 结果，优先选择保留原文或手动编辑。
- 删除类操作风险最高，应用前建议确认。
- 大清洗和旧记忆归档不建议一次处理太多。
- 除「清理新增」外，其他整理操作结束后建议使用「修复记忆顺序」。
- 结果区只是草稿，点“应用全部结果”后才会真正写回。
